# ToastBox Hy2 修改意见汇总

日期：2026-11-17。用途：交给 Gemini 执行修复及新增功能。本清单汇总上一轮审查的五项问题，并补充公共证书自动申请需求；尚未实施这些修改。

原实施背景参见 [Hy2 证书与端口跳跃规划](HY2_CERTIFICATE_AND_PORT_HOPPING_PLAN.md)。执行前先核对当前工作树，保留已有未提交修改；若某项已修复，验证后跳过重复改动。下列行号对应审查时版本。

## 1. [P1] 修复禁用 IPv6 时开启端口跳跃会提前退出

位置：src/lib/35-hy2-hop.sh 的 hy2_hop_families，约第 212-223 行；调用处为 hy2_hop_preflight。

触发条件：系统禁用 IPv6，使用默认空监听地址或 ::，安装时开启 --hy2-hop-ports。

当前 ipv6_enabled && HY2_HOP_V6=1 在 IPv6 不可用时返回 1，使整个函数返回失败。安装流程裸调用该函数，在 set -e 下直接退出。已用严格 Bash 模式复现。

修改要求：

- IPv6 不可用时保留 IPv4 规则能力，地址族判断正常完成后明确返回成功。
- 保持显式 IPv4、显式 IPv6和双栈监听的既有行为。
- 补一个真正模拟 ipv6_enabled 返回 1 的安装流程测试，不能继续把所有测试都固定为 IPv6 可用。

验收：系统禁用 IPv6、默认监听、开启跳跃时安装成功，生成 IPv4 转发配置，且不会尝试创建 IPv6 规则。

## 2. [P2] 修复证书钩子可能调用旧版 ToastBox 入口

位置：src/lib/56-cert-hook.sh 的 certbot_ensure_entrypoint，约第 41-54 行，尤其是第 47 行。

触发条件：机器上已有不支持 refresh-cert 的旧版 /usr/local/bin/toastbox，从新版源码入口安装节点并启用 Certbot 钩子。

当前代码发现入口可执行就直接返回成功，跳过从当前源码构建新版入口。钩子安装看似成功，实际续期时却由旧入口报未知命令，证书不能同步。该路径已复现。

修改要求：

- 从源码启用钩子时，确保持久管理入口对应当前实现；不能仅以文件可执行作为条件。
- 可复用现有构建和安装能力更新入口，保留单文件安装方式的行为。
- 补一个旧版入口已存在的回归场景，验证最终钩子能实际执行 refresh-cert。

验收：已有旧版入口时，从新版源码安装钩子后，匹配的证书续期能够更新节点证书，不再出现 unknown command refresh-cert。

## 3. [P2] 修复生成单文件的 ShellCheck 失败

位置：src/lib/55-tls.sh 的 tls_cert_matches_name，约第 46-54 行；src/lib/35-hy2-hop.sh 的 norm_hy2_hop_ports 局部变量声明。

当前两个函数的同名局部变量 out 分别被用作数组和标量。整合脚本触发 ShellCheck SC2178/SC2128，项目 lint 阶段无法通过。这是静态检查中的类型推断冲突，不应描述成已证实的运行时变量串扰。

修改要求：

- 为其中的局部变量使用含义明确的独立名称。
- 修改 src 后重新生成 toastbox.sh，不手工修补构建产物。
- 按现有 Makefile 运行完整 lint，避免通过全局屏蔽检查来掩盖问题。

验收：构建一致性检查、ShellCheck 和 shfmt 均通过。

## 4. [P2] 修正单元测试的状态夹具和旧日志断言

位置：tests/unit/hy2-extensions.bats 第 127 行附近；tests/unit/flow.bats 第 453、474 行附近。

第一个问题：旧 files 状态测试在父进程调用 state_json，但实际安装在 run_toastbox 的子进程完成，父进程 CFG 尚未加载已安装节点。生成的数据把 Hy2 写成未启用，因此实际错误是 Hysteria 2 is not enabled，既没有测试预期的来源路径缺失分支，也没有继续验证后面的状态保存失败回滚。

第二个问题：部分旧测试要求“停止或恢复内核”必须是 MOCK_LOG 最后一行；新增 NAT 清理日志后，这种断言会失败，即便内核恢复动作已经执行。

修改要求：

- 从实际保存的 state.json 构造缺少来源路径的旧状态，或先 state_load；经临时文件写回，避免读取时截断原文件。
- 将日志断言改为验证对应内核操作是否发生、次数和必要顺序，允许无关的 NAT 清理日志存在。
- 确认修正后的测试能分别走到“缺少来源路径”和“state_save 失败回滚”两个预期分支。

验收：上述测试在 Linux 上通过，且仍能检测缺失的回滚动作。Windows 的路径、符号链接和 POSIX 权限差异需与实际逻辑错误区分，不把环境失败全部当作项目故障。

## 5. [P2] 修正 UFW 端到端测试的准备顺序

位置：tests/e2e/run.sh 第 547-555 行附近。

触发条件：测试机器装有 UFW，但 UFW 初始未启用。

当前先运行 ToastBox 部署，再开启 UFW，随后立即要求存在 8443/udp 放行规则。ToastBox 部署时检测到 UFW 未启用，会按现有设计跳过规则同步；后续启用 UFW 不会自动补上规则，因此该用例会失败。

修改要求：

- 在待测安装之前启用 UFW，或在启用后重新执行安装以触发规则同步。
- 再验证 NAT 后的实际监听端口已放行，并从网络命名空间进行真实跨跳通信。
- 沿用一次性测试环境和现有清理流程，不在用户日常主机运行这套安装/卸载测试。

验收：初始 UFW 关闭的干净 Linux 测试环境能够通过该用例，且通信确实经过 PREROUTING 和 UFW INPUT 路径。

## 6. [新增功能] 不依赖 ToastWeb，自动申请并维护公共证书

目标：部署 Hy2 时，用户可以显式选择由 ToastBox 调用 Certbot，自动申请 ECDSA 公共 CA 证书，接好续期和证书同步，无需部署 ToastWeb 或常驻网站。

当前状态：ToastBox 已自动生成自签证书，也支持导入公共证书和安装续期同步钩子；尚未接入首次公共证书申请及续期调度。--hy2-cert-hook certbot 本身不会申请证书。

### 6.1 首版实现范围

- 继续保留默认 self-signed 模式和现有 files 导入模式；自动申请公共证书由用户显式选择。
- 两种服务端内核统一使用外部 Certbot，不改用官方独立 Hysteria 服务端，也不分别建设两套签发流程。
- 首版实现 Certbot standalone 的 HTTP-01 域名验证。该模式只在验证期间临时监听 TCP 80，不依赖 Nginx 或 ToastWeb。[Certbot 官方说明](https://eff-certbot.readthedocs.io/en/stable/using.html#standalone)
- DNS-01 可作为后续按服务商插件扩展的功能，不要求首版接入所有 DNS 平台。

### 6.2 用户输入与签发流程

1. 增加明确的公共证书自动申请入口，收集域名、账户邮箱及必要的 CA 条款确认。参数命名沿用现有 CLI 风格，在帮助和中英文 README 中明确列出；非交互模式不能靠交互补齐必要输入。
2. 检查域名解析和验证所需的公网 TCP 80 条件，说明云安全组和本机防火墙的要求。TCP 80 被其他服务占用时明确报错，不自动停止现有网站或代理。后续续期也需要满足验证条件。
3. 安装/使用 Certbot，通过 certonly --standalone 申请 ECDSA 证书。使用独立 lineage，例如 toastbox-hy2-<domain>，便于复用当前基于 lineage 匹配的钩子。
4. 已有有效证书时复用，重复安装不强制重新签发；签发失败保留已有可用节点，输出明确原因，不静默改成另一种信任方式。
5. 申请完成后将稳定的 live/fullchain.pem 和 live/privkey.pem 路径交给现有 files 导入流程。建议把 ACME 作为证书获取步骤，state 中继续使用 tls=files，复用 refresh-cert，避免为了签发方式重复建设客户端信任逻辑。
6. Hy2 SNI 默认采用申请域名；如果用户显式指定其他 SNI，仍按现有证书名称匹配逻辑校验。

### 6.3 自动续期与同步

- 检测并复用系统已有的 Certbot 定时续期任务。没有可用任务时，为本项目证书建立限定范围的定时续期任务，避免重复调度。
- 自动申请模式默认接入本项目的 Certbot deploy hook。续期成功后由 hook 调用 refresh-cert，将新证书副本写入当前内核配置。
- 复用完整证书链比较、内容未变不重启、原服务停止则保持停止、失败恢复和操作锁等现有机制。
- 公共证书客户端继续正常 CA/域名校验，不添加 insecure 或固定叶证书指纹；正常续期不应要求更新客户端配置。
- 文档说明刷新内嵌证书会重启当前内核并可能短暂中断连接；不要称为无中断热加载。
- 关闭自动化或卸载时，仅清理 ToastBox 自己的钩子及专属任务；共享 Certbot 定时器、账户和证书不随节点卸载删除。

### 6.4 验收

- 没有 ToastWeb/Nginx 的隔离 Linux 环境中，自动申请模式能完成签发入口、导入和启动流程。
- 已部署 ToastWeb 的用户仍可继续使用现有 files 导入，不被自动申请模式要求重新签证书。
- 自签、外部文件导入、Certbot 自动申请三条使用路径都有对应说明；未选择自动申请时不额外调用 Certbot。
- 重装复用证书，定时续期可执行，匹配 lineage 的续期钩子能更新实际在服证书，节点密码、协议及跳跃设置保持。
- 单元测试模拟 Certbot 成功/失败与续期，隔离 Linux 验证任务和钩子。具备获准使用的测试域名时再用 CA staging 做真实签发和续期演练；未实际完成的验证需如实记录。
